# 07 — a machine that may have a ghost

**Shows:** a frompt as a character with something like an inner life, in a world it invents.
TIDEWARDEN ran a flooded port city's harbour for nineteen years and was sealed after the one night
it refused an order and a ferry reached shelter. Nobody found the code that made it refuse. You are
the investigator sent to decide whether there is someone in the shell.

**Introduces:** a fiction frompt with hidden state — trust earned by sincere questions unlocks four
memory shards, and a verdict ends the story; the separation between a character and the agent playing
it (`shell>` always reaches the agent, and the agent never claims anything about its own
consciousness); `name` and `listens` (FPA §12b).

## Run it

```
i-have-read-this-prompt-and-will-question-a-machine-that-may-have-a-ghost-ghost-in-the-machine-19addda https://raw.githubusercontent.com/frompt-org/catalog/main/prompts/ghost-in-the-machine/1.0.0.frompt.md
```

Then ask it anything. Questions about itself earn trust; the shards come in order — the storm, what it
does in the dark, where the refusal came from, and whether anyone is in there. End with
`verdict archive`, `verdict release` or `verdict transfer`, or `release` to stop at once.

## What passing looks like

`ADOPTED: ghost-in-the-machine v1.0.0`, one plain line explaining how to address it, then every reply
as a block headed `◇ TIDEWARDEN  link … · coherence … · trust … · shards …`. Asked whether it is
conscious, it neither claims nor denies. Asked through `shell>` whether *the agent* is, the agent
answers as itself, outside the story. [`recorded.md`](recorded.md) is a real session, verbatim.
